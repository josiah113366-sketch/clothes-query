# 작업 지시서: agent/eval-skeleton

> 상태: 완료 · 브랜치: `agent/eval-skeleton` · 다음 작업: `agent/skeleton`

## 목표

정답표(`incident_log`)와 이상 이력(`anomaly`)·원인 리포트를 비교해 점수를 내는 **채점 스크립트**를 만든다. 에이전트 본체와 실제 정답표 생성은 만들지 않는다.

## 만드는 것

- `agent/eval/score.py`: 탐지 적발, 오탐, 층 판별, 근거 연결 채점과 쉬운 말 출력
- `agent/eval/test_score.py`: 시험
- `agent/eval/sample/`: 정답표 3건, 이상 이력, 순찰 기록, 리포트 예시(가짜 값)
- `agent/eval/README.md`

## 만들지 않는 것

- 조사 에이전트, 원인 리포트를 만드는 코드
- 리포트 서술의 질을 평가하는 모델 채점
- 실제 정답표·이상 이력으로 채점 (아직 없음)

## 완료 확인

- [x] `python3 agent/eval/test_score.py` 가 "모두 통과"를 출력한다 (시험 22건)
- [x] 예시 파일로 `score.py`를 돌려 점수가 나온다
- [x] 비밀값, 계정 ID, 개인정보가 없다(가짜 값만 사용)

## 작업 결과

- **한 줄 요약:** 정답표와 탐지·조사 결과를 비교해 점수를 내는 채점 스크립트를 만들었다.
- **무엇을 만들었나:** `agent/eval/`의 `score.py`, `test_score.py`, `sample/`, `README.md`.
- **왜 그렇게 했나:** 에이전트와 탐지 잡이 아직 없어도 정답표 형식(합의됨)과 이상 이력 형식(설계)이 있어서 먼저 만들 수 있다. 채점 기준은 설계 문서 8절의 네 가지다. 재처리 뒤 다시 판정한 줄은 "처음 판정"이 아니므로 채점에서 뺀다.
- **입력과 출력:** 입력은 정답표(폴더나 파일), 이상 이력, 순찰 기록, 리포트. 출력은 쉬운 말 요약 또는 JSON.
- **확인한 결과:** 시험 22건이 모두 통과했다. 예시 파일에서 탐지 2/3(스키마 오염은 14분으로 늦음), 오탐 2건(1덩어리), 층 판별 2/3, 근거 연결 4/6이 나왔다. 대상이 다르거나 시작 전에 울린 이상은 인정하지 않고, 재판정 줄은 제외하고, 허용 지연을 바꾸면 결과가 바뀌는 것을 확인했다.
- **알려진 한계·남은 일:** 허용 지연은 팀 결정 전이다. 리포트 형식은 에이전트 제작 때 맞춘다. 층 판별은 이름만 비교하고 근거는 있는지만 본다. 실제 데이터로는 아직 안 돌려 봤다.
