# Silver·Gold A 최종 실행 연결

상태: 구현·검증 및 사용자 검수 완료 · 커밋/PR 제출 진행

## 승인 범위

- 결제 UPDATE를 Gold B #95의 최신 Kafka 위치 기준에 맞춘다. legacy Bronze는 기존 처리다.
- 시간대·주문 부분 교체까지 구현한다(사용자 선택). 대상 주문의 전체 이력은 읽되 대상 밖 상태는 이전 완료 실행에서 보존한다.
- 거래·퍼널·리뷰·재처리 DAG 4개와 Gold A 6개 결과·보류 목록의 실행 ID 고정 공개를 연결한다.
- 리뷰 점수는 Iceberg 최신 뷰를 조회해 실행별 Parquet으로 고정한다. 공통 YAML·지문 알고리즘·Gold B 코드는 변경하지 않는다.
- 원본 금액 복구 SQL은 사용자가 나중에 전달한다. SQL 검수·실제 DB 복구는 아직 수행하지 않는다. 재처리를 원본 복구로 표시하지 않는다.
- 구현 검수 후 범위별 커밋·PR·main 반영과 최종 이미지 발행을 진행한다. 브랜치 대장은 이번에 수정하지 않는다.

## 작업 결과

- `payment_state.py`와 거래 처리: 단일 Kafka 파티션의 최신 offset 선택, UPDATE, 과거 오류의 active 분리, 최신 위치 보존. 원천 시각 역행·다중 파티션·마지막 오류는 보류한다. 과거 오류에 원천 시각이 없는 것만으로 최신 정상 상태를 막지는 않는다.
- `reprocess.py`와 Spark 병합: 승인 입력으로 원본 객체·ETag·기준 실행 고정, 주문별 품질 집계와 대상 밖 상태 보존, 연결 주문 범위 추적, STARTED/LEDGER_REPLACED/FAILED 인계. 원본 금액을 수정하거나 VERIFIED를 쓰지 않는다. 새 코드의 기준 거래 배치가 선행해야 한다.
- `review_scores.py`, `gold_publication.py`, Gold DDL: 최신 Iceberg 뷰의 실행별 Parquet 조회 고정, 실제 모델 번호·버전 보존, Gold 6개 지표와 보류 목록의 완료 실행 공개. 실시간 AWS Athena UNLOAD는 아직 수행하지 않았으며 가짜 AWS와 실제 Spark 어댑터를 나눠 검증했다.
- DAG 4개와 S3 거래 실행 잠금: 업무별 요청 검사·Spark 실패 전파·R6/Gold 공개·재처리 결과 기록을 연결한다. 운영 주기는 임의로 추가하지 않고 수동 상태를 유지한다.
- 운영 Python 3.10.12/PyArrow 25의 회귀 113개 통과. 별도 생산자 소스를 직접 import하는 시험 1개는 제외하고 실제 Python 3.12 생산자가 쓴 파일을 3.10 Silver가 읽는 방식으로 별도 통과했다. 생산자의 Python 요구 버전을 업무 이미지에 강제하지 않는다.
- 실제 Spark 4.2 거래·퍼널 기존 회귀 10개, 신규 UPDATE/부분 교체 2개 통과. 부분 교체에서 대상 밖 변경을 보존하고 MISMATCH→복구 입력→PASS를 확인했다. 최종 후보에서 부분 복구·퍼널 재실행과 배포 DDL의 타입/순서도 재검증했다.
- Spark 리뷰 5개 통과: 파일/빈 결과/오류 보존/혼합 최신 모델/고정 Athena 결과 어댑터. 실제 Parquet과 DDL 대조에서 리뷰 날짜를 DATE로 정렬했다. 실제 운영 Glue 최신 뷰의 컬럼·타입은 읽기 전용 확인했다.
- 실제 Airflow 이미지에서 4개 DAG·Pod 신원·준비 태스크 순서·실패 watcher 3개 통과. Ruff(py310), git diff --check 통과. 공통 YAML·지문 알고리즘·Gold B 코드는 수정하지 않았다.
- 후속 배포: main 반영 후 해당 코드로 최종 이미지를 발행한다. 재영 담당의 Glue DDL/Driver 권한/Airflow 환경 설정과 운영 수동 실행 검증이 남아 있다. 주현 담당의 R6 순차 소비·VERIFIED 연결과 실제 원본 복구 SQL 실행은 별도다.
