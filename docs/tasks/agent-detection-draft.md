## 작업 결과

- **한 줄 요약:** 탐지·조사 에이전트 영역의 초안 코드(신뢰성 쿼리, 규칙 프로토타입)를 올렸다.
- **무엇을 만들었나:** `agent/reliability/`(SQL, 시험 코드, README), `agent/prototype/`(데이터 생성, 규칙, 평가, 보고서), `agent/README.md`.
- **왜 그렇게 했나:** 팀이 탐지 주기(5분)와 규칙의 근거를 숫자로 볼 수 있게 하려고, 가짜 데이터로 30회 반복 시험한 코드를 그대로 공개했다.
- **입력과 출력:** 입력은 Gold B 원장 테이블 이름(가정). 출력은 시험 결과 표.
- **확인한 결과:** 신뢰성 쿼리는 누락 3개, 메시지 중복 5개, 결제 중복 4개를 모두 찾았고 정상 장부에서는 0이었다. 프로토타입(규칙 R1 최근 15분 PG 원인 실패 3건 이상, 가짜 데이터 30회)에서 PG 장애 탐지 시간은 판정을 1분마다 돌렸을 때 하루 900건 평균 11분(최대 28분), 하루 3,600건 평균 3분(최대 6분)이었고, 판정을 5분마다 돌렸을 때 하루 900건 평균 13분(최대 30분), 하루 3,600건 평균 5분(최대 10분)이었다.
- **모드별 결과:** `agent/prototype/modes.py`로 시뮬레이터 확률표(10/16)의 모드별 주문량을 쟀다(판정 5분마다). 평소 PG 원인 실패가 없다고 가정하면 PG 장애는 하루평균 이상 모드에서 5분(판정 한 번) 안에 잡혔다. 평소 PG 원인 실패 1.15%를 넣으면 고정 3건 기준은 오탐이 늘어(하루평균 4건, 저녁 피크 10건, 중간 56건) **주문량에 맞춰 바뀌는 기준이 필요**하다.
- **알려진 한계·남은 일:** 쿼리는 Athena에서 실행하지 않았다. 프로토타입은 실제 시뮬레이터 모드로 재지 않았다. 허용 지연은 미확정이다.
