## R6 준비 및 적용 조건

새 설정은 `silver_checks_table: silver.order_amount_checks`, `silver_runs_table: silver.silver_runs`다. 두 표를 정확히 묶어 준비 도구에 허용하며 다른 DB/표로 확장하지 않는다.

실제 detection-job 신원의 작은 Pod에서 Glue silver DB·표 조회와 두 Athena SELECT가 모두 성공했고 결과 읽기도 통과했다. 검사 표는 0 bytes, 완료 표는 302 bytes를 스캔했으며 원본 쓰기는 없다. 검증 Pod는 삭제했다. 권한은 이미 적용된 범위여서 중복 IAM 정책을 생성하지 않았다.

현재 판정 이미지는 기존 digest다. 새 digest를 받으면 ECR 존재와 코드 기준을 확인하고 기존 ConfigMap을 보존 병합한 뒤 적절한 배포 창에 재시작·실제 환경변수 전달·수동/예약 성공을 확인한다. 이번에는 운영 ConfigMap을 바꾸거나 R6를 켜지 않았다.

## 공개 저장소 이미지 식별자

사용자가 승인한 [공유 배포 정책](../../infra/DEPLOYMENT_CONFIG.md)에 따라 계정 ID·일반 ARN·버킷·리소스 이름을 공유한다. ECR URI와 digest는 이미지 식별자이며 pull/push 자격증명이 아니다. 현재 고정 digest 배포 형식은 유지할 수 있다. AWS 키·ECR 로그인 토큰·비밀번호는 별도 Secret/인증 경로로 공급한다.

dashboard deploy.ps1은 ECR push 후 digest를 deployment.yaml에 기록하는 기존 구조다. 식별자까지 숨기려면 생성 manifest를 비추적 runtime 파일로 분리하는 작업이 필요하지만 보안 사고 대응을 이유로 급히 삭제하거나 이력 재작성을 할 근거는 확인되지 않았다. 이번에는 동료 배포 방식을 임의로 바꾸지 않았다.
