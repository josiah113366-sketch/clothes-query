# Silver 회원·클릭 공통 입력 검사 연결

## 승인 범위

- 사용자 요청으로 PR별 범위를 분리한다. 최신 main에서 회원·클릭 Silver가 확정된 공통 규약 0.2.0을 호출하도록 연결한다.
- 회원 CDC 변경 순서·현재 상태 복원, 클릭 중복·충돌 처리, 출력 시간대·경로는 유지한다. 형식 검사만 공통 검사기를 사용한다.
- 오류의 field/code/rule_id를 기존 격리 기록에 연결하고 실행 시 읽은 규칙 버전·SHA-256·경로를 품질 결과와 manifest에 남긴다. CLI --rules-path로 동일한 규칙 파일을 지정할 수 있게 한다.
- 기존 테스트 파일의 정상 입력을 UUID·상품 키 형식에 맞추고 입력 오류·재실행·이전 공개 결과 보호를 확인한다. 새 테스트 파일은 만들지 않는다.
- 공통 YAML·Gold B 코드·거래 실패 코드 정책·Gold A 코드는 수정하지 않는다. 미등록 코드 수용은 담당자의 후속 공통 규약 변경을 받은 뒤 별도 작업으로 적용한다.
- 회원·클릭 검사 버전은 members.v2·clicks.v2로 구분한다. push·PR 생성·머지는 별도 승인 전까지 하지 않는다.

## 완료 확인

- 회원 UUID·허용 값·탈퇴 시각·금지 개인정보 필드와 클릭 UUID·상품 키 10자리 검사가 기존 격리에 연결된다.
- 원천 시각/CDC 참조, 기존 중복 제거·현재 상태 복원과 UTC/KST 변환을 유지한다.
- 규칙 파일 오류는 행 격리가 아니라 실행 실패로 전달하고 이전 current.json을 보존한다.
- 기존 Silver 및 공통 검사기 회귀, 변경 코드 Ruff·diff 공백 검사와 PR 파일 범위를 확인한다.

## 작업 결과

- 회원·클릭 입력에 공통 validate()를 연결하고 정상 출력의 그레인·경로·시간대와 CDC/중복 복원을 유지했다. 공통 수집기는 FormatError의 첫 오류를 격리하며 rule_id를 보존한다.
- 실행에 규칙을 한 번 읽고 품질 결과·manifest에 version/sha256/path/consumer를 남긴다. 회원·클릭 CLI에 --rules-path를 추가했다. 기존 회원/클릭 시험 ID를 UUID로 맞췄다.
- 회원·클릭 집중 검증 9개 통과(1.87초). Silver·공통 검사기·Gold B 샘플 회귀 88개 통과·1개 건너뜀(4.23초). 건너뛴 것은 pyarrow 미설치에 따른 Gold B Parquet 시험이다. 변경 코드·기존 테스트 Ruff 및 diff 공백 검사 통과.
- 공통 YAML·지문 함수·Gold B·거래 실행 코드·Gold A는 변경하지 않았다. 미등록 실패 코드 수용 정책은 은서의 후속 규약을 기다린다. push·PR 생성·머지는 하지 않았다.
- Gold A는 별도 브랜치에서 0.2.0 main과 동기화하고, 시험 상품 키를 10자리·클릭 이벤트 키를 UUID로 맞췄다. 두 PR 파일을 임시 복사본에서 함께 검증해 전체 pipelines 106개 통과·1개 건너뜀(14.15초)을 확인했다. Gold A와 Silver 브랜치는 서로 병합하지 않았다.
