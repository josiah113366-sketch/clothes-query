# 공통 결제 내용 지문 함수

## 승인 범위

- 사용자 승인으로 pipelines/payment_fingerprint.py에 9개 필드 순서·정수/NULL/시각 정규화·JSON 직렬화·SHA-256·지문 버전을 구현한다.
- 사람용 규약은 docs/contracts/README.md에 추가하고 기존 거래 테스트 파일에 검증을 추가한다. 새 테스트 파일은 만들지 않는다.
- 최신 main 기반으로 R6 출력·Kafka 추적·최소 단가 변경과 분리한다. 브랜치당 지시서 규칙에 따라 이 파일에 기록한다.
- Silver/Gold B 실제 호출·저장·뷰 변경 및 미등록 코드 수용·입력 YAML 변경은 이번 범위 밖이다.

## 완료 확인

- 고정 JSON 바이트·SHA-256 벡터·UTC/KST 등가성·전달 메타데이터 제외를 확인한다.
- 업무 내용 변경은 지문 변경, bool/실수/문자열 금액·누락·시간대 없음·과도한 시각 정밀도는 거부하는지 확인한다.
- 원본 수정 없음, 기존 입력 허용 정책 미변경, Silver 회귀 및 Ruff/diff 검사를 확인한다.

## 작업 결과

- 계약 검토 후 수정 승인: 기존 YAML과 동일하게 SUCCESS에서 생략된 failure_code를 명시적 null과 같은 지문으로 정규화한다. FAILED의 생략/null/빈 문자열/공백은 계속 거부한다. 입력 객체는 수정하지 않는다.
- 호출 규약 보완: 양쪽은 공통 입력 검사 후 원천 시각 문자열로 지문을 계산하고 그 이후 datetime/Spark 시각 변환을 수행한다. 기존 Silver UTC 결과를 재매핑해 7자리 정밀도 손실을 감추는 경로는 계약에서 제외했다. 실제 양쪽 호출 연결은 아직 미구현이다.
- 수정 검증: Silver 테스트 32개 통과(1.86초), 공통 모듈 Ruff 및 diff 공백 검사 통과. YAML 통과 후 SUCCESS의 필드 생략/명시적 null 지문 일치와 원본 불변, FAILED의 누락/빈 값 거부, 요청·완료 시각 각각 7자리 소수초를 원문 단계에서 거부함을 확인했다. 기존 고정 해시 벡터는 바뀌지 않았다. 배포 전 v1 초안 수정이며 실제 저장된 지문 마이그레이션은 수행하지 않았다.

- 공통 함수 payment_fingerprint가 해시/버전을 반환하며 canonical_payment_content로 규약 바이트를 확인할 수 있다. v1은 시간대 포함 ISO 문자열을 UTC 소수초 6자리 Z로 변환한다. 6자리 초과는 정밀도 손실 방지를 위해 거부한다.
- Gold B 최신 DDL에 두 컬럼이 추가된 것을 확인했다. 지문 계산 규약은 아직 공동 확인 대상이며 실제 Silver/Gold B 호출은 연결하지 않았다.
- 최종 검증 결과는 실행 후 기록한다. push/PR/머지는 하지 않는다.
- 최종 검증: main 기반 Silver 테스트 31개 통과(2.81초), 신규 공통 모듈 Ruff 및 git diff --check 통과. 고정 바이트/해시 벡터, 입력 키 순서 무관·UTC/KST 동등 시각·마이크로초 차이·모든 업무 필드 변경·원본 불변·메타데이터 제외·유효하지 않은 타입/누락/정밀도 거부를 기존 테스트 파일에 추가했다. 기존 미등록 코드 입력 검사는 계속 오류인 것도 확인했다. 추가 패키지·AWS·모델 호출 없음.
