# 대시보드 공용 노드 통합

2026-10-24 사용자가 대시보드를 기존 공용 노드로 옮기도록 승인했다.

- 이동 직전 대시보드 실제 사용량은 CPU 5m·메모리 150MiB, requests는 250m·512MiB였다. 기존 Kafka·Airflow 공용 노드의 예약 여유 480m·약 2GiB에 들어감을 확인했다. 한 시점의 사용량은 최대 부하 보장이 아니다.
- 대시보드만 있던 추가 공용 노드의 새 배치를 일시 차단하고 Deployment를 순차 재시작했다. 새 Pod Ready 후 이전 Pod가 종료됐다.
- 대시보드 이미지·Secret·계정·환경 변수·자원·Service·ALB·배포 전략은 바꾸지 않았다. 특정 hostname 고정 설정도 추가하지 않았다.
- 새 대시보드는 기존 Kafka·Airflow 노드에서 Running·Ready이며 실제 내부 8501 포트의 health 응답은 HTTP 200이다. 브라우저 세션 재연결이 전혀 없었음을 보장하는 시험은 아니다.
- 원래 노드에 비종료 일반 업무 Pod가 없고 DaemonSet만 있음을 확인한 뒤 UID/소유 관계가 일치하는 NodeClaim 하나만 명시적으로 해제했다. Kafka·Airflow·Spark 노드는 유지했다. 유휴 자동 통합 성공으로 표현하지 않는다.
- 기존 추가 노드의 최초 생성 이유는 확정하지 않았다. 16:44 대시보드 재배포와 16:45 노드 생성의 시각상 연관만 확인했다.

노드 한도나 롤링 배포의 surge 정책은 바꾸지 않았다. 추후 대시보드 재배포·다른 작업의 예약량에 따라 공용 노드가 다시 늘 수 있다. 재발 방지를 위한 배포 시 순간 자원·여유량 정책 조정은 별도 검토 사항이다.
