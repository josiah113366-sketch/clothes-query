# 작업 지시서: sim/console

> 상태: 진행 중 · 브랜치: `sim/console` (최신 `main`) · 설계: `docs/design/api.md` 12절 범위 메모(2026-10-20)

## 목표

컨트롤러 화면을 시뮬레이터 콘솔로 키운다. 시작·정지, 모드 전환, 장애 주입·정답표는 그대로 두고 **트래픽 보기**를 더한다. 업무 분석(매출 등)은 Gold 담당, Kafka 상세는 Kafka UI, 원인 분석은 에이전트라 넣지 않는다.

## 이번 작업의 특례 (사용자 결정, 2026-10-22, 다른 문서보다 우선)

- 접속: **지금처럼 ECS Exec 포트 포워딩**(AWS 권한이 있는 팀원). 공개 ALB는 만들지 않는다
- 시뮬레이터 숫자 전달: **공유 볼륨 숫자 파일**(`stats-<이름>.json`, 2초). 모듈끼리 import하지 않는 규칙을 지킨다
- 그래프 기록: **컨트롤러 메모리 30분**(새로고침해도 유지)
- 화면: 보기 좋고 애니메이션이 있는 UI. 외부 CDN 없이 HTML 한 장
- 재배포로 예약 큐가 사라지는 것은 감수한다(3일 분석 기간 중이어도)

## 만드는 것

- `common/stats.py`: 숫자 파일 쓰기(원자적 교체, 실패해도 계속)·읽기
- `behavior`·`member` 실행기: `stats` 콜백으로 2초마다 누적 숫자(PII 없음)
- `controller/traffic.py`: Prometheus 텍스트 파싱, 화면용 요약, 30분 표본 기록
- `controller/server.py`: `GET /api/traffic?since=`, 표본 스레드
- `controller/page.py`: 콘솔 화면

## 만들지 않는 것

- 공개 접속(ALB, 도메인), RDS 직접 조회, 표본의 디스크 저장

## 작업 결과

- **한 줄 요약:** 컨트롤러 화면에 실시간 트래픽(보낸 것 vs 받은 것)을 더한 시뮬레이터 콘솔
- **확인한 결과:** ruff 통과, pytest 422 통과(추가 10개). 로컬 데모 화면 확인
- **알려진 한계·남은 일:** API Pod가 여러 개가 되면 /metrics가 한 Pod 숫자만 보인다. 클릭 전송 실패 수(시뮬레이터 쪽)는 아직 화면에 없다(API의 Kafka 발행·5xx로 본다)
