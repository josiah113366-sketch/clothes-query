# 도쿄 비용 알림

상태: 실제 적용·API 대조·변경 없음 확인 완료. 작업 브랜치: `infra/applied-state-sync`.

2026-10-24 사용자는 Gold B 버전을 담당자가 기존 환경에 맞추는 방향으로 두고 비용 알림을 진행하도록 요청했다. 월 $200과 누적 10% 간격 알림을 확정했다. 기존 이메일 수신자를 그대로 사용하며 실제 이메일은 Git에 넣지 않는다.

## 구현

- 기존 RDS 알람 5개가 이미 있어 옛 operations-alerts 초안은 적용하지 않았다.
- cost-budget 독립 state·모듈·공유 계정/월 기준 설정만 추가한다.
- 동일한 도쿄 월 $200을 관측하는 예산 3개에 실비 10~50%, 60~100%, 월말 예상 100% 알림을 나눴다. AWS 예산당 알림 5개 제한을 지키며 합산 $600 예산이 아니다.
- 세금·크레딧·환불을 제외한 unblended 비용이며 지원 크레딧 차감 후 청구액과 다를 수 있다. 글로벌·다른 리전 비용은 포함하지 않는다.
- Budget Action·SNS·새 CloudWatch 알람·유료 정기 보고서·컴퓨트는 만들지 않는다.

## 검증

Terraform mock 4개(도쿄 한정·11개 알림·잘못된 금액/수신자 차단), stack validate와 diff 검사를 통과했다. 실제 plan은 Budget 3개 추가뿐이며 기존 자원 변경·삭제는 없다. plan·state·실제 이메일은 Git 제외 경로에 저장했다. 최신 main 8251145(#101·#87·#103 포함)를 브랜치에 먼저 반영했다.

추가 뒤 전체 Terraform 24 roots init/validate와 23 mock suites / 102 plan도 통과했다. 공개 변경 검사에서 앱 코드 변경 없음·원본 적용 후속 브랜치 8개 보존·개인 수신자 미포함을 확인했다.

## 작업 결과

예산 3개를 실제 생성했고 적용 뒤 Terraform plan 변경 없음이다. Budgets API에서 도쿄 필터·월 $200·실비 10개와 예측 1개 알림·기존 수신자 일치를 모두 확인했다. API가 생략하는 기본 percentage 유형은 갱신된 Terraform 값과 무변경 계획에서도 확인했다. 기존 RDS 경보는 변경하지 않았다.

이메일 도착은 API 설정 확인과 구분하며 아직 수신 확인 전이다. 비용 집계가 지연되므로 실시간 경보가 아니며 이미 지난 기준의 알림이 함께 올 수 있다. 실제 수신자·state·plan·원문 검증 로그는 Git 제외 경로에 보존했다.
