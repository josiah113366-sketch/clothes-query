# 공용 데이터 플랫폼 준비 계획

상태: 제안 · 조사일: 2026-10-14 (KST) · 계획 문서 작성 완료, 구현·배포 미실행

이하 내용은 계획 브랜치 작성 당시의 기록이다. 이후 승인된 Kafka 자체 운영과 로컬 구현·검증은 [현재 인프라 지도](../../../infra/README.md), [데이터 경로 준비 현황](../infra/data-path-readiness.md), [통합 작업](../../tasks/infra-local-ready.md)을 따른다. 이 계획의 미정 항목 전체가 구현 승인된 것은 아니다.

## 이번 작업의 범위

사용자가 제공한 전체 흐름도의 `[2 플랫폼]`을 인프라 담당의 범위로 정리한다. 제네레이터, Consumer 처리 로직, Spark 변환 코드, Airflow DAG, 대시보드 업무 지표, 탐지 규칙 및 에이전트 구현은 포함하지 않는다. 이 문서는 해당 담당자가 서비스를 실행할 수 있도록 필요한 기반과 인수인계 조건을 정하는 계획이다.

## 기준과 브랜치 분리

- 계획 브랜치: `infra/platform-plan`. `git fetch origin` 후 확인한 `origin/main`의 `f0a6059`에서 생성했다.
- 기반 인프라 참고: 별도 브랜치 `infra/analysis`의 `7cdd4d5`. 조사 시점에 이 커밋은 `origin/main`에 미병합이다.
- 이 브랜치에는 기반 Terraform을 복사하거나 병합하지 않는다. 따라서 여기서 `infra/stacks/`가 보이지 않는 것은 코드 유실이 아니다.
- 기반 구현과 기존 검증 결과는 참고 커밋의 코드·작업 기록으로 확인했다. 이번 작업에서 Terraform 검사나 AWS 상태 조회를 다시 수행하지 않았다.
- 상위 폴더의 `infra_reuse_analysis.zip`은 읽기 전용 참고 자료다. ZIP을 배포 코드로 실행하거나 전체 추출하지 않았다.
- 기존 `infra/analysis` 작업 폴더를 유지하고, 별도 Git worktree에서 신규 문서만 작성한다. push·PR·AWS 변경은 수행하지 않는다.

이 계획을 병합한 뒤 후속 구현 브랜치를 만들 때에는 최신 main에 기반 인프라가 병합됐는지 먼저 확인한다. 다른 PC의 미커밋 작업은 이 조사에 포함되지 않는다.

## 결정 / 제안 / 미정

**결정:** 인프라 담당의 작업만 수행하고 제네레이터 구현을 제외한다. 여기서는 실제 배포하지 않는다. 기존 Git 구조·state와 다른 PC의 기반 작업을 보존한다.

**제안:** Kafka/Connect의 실행 기반을 첫 후속 구현으로 검토한다. 그전에 영구 볼륨, CDC, 용량, 권한과 관리 주체를 합의한다. 모니터링·로그와 CI는 별도 브랜치로 분리한다.

**미정:** Kafka 운영 방식·버전·규모·보존 기간, Spark 실행 방식, Airflow executor와 metadata DB, Secret 공급 도구, 플랫폼 자원 예산, 모니터링 제품. 기존 실습 기본값을 결정으로 취급하지 않는다.

## 바로 이어갈 일

1. [팀원 입력표](ownership.md)의 필수 입력을 모은다. 모든 장기 기능을 한 번에 확정할 필요는 없다.
2. [결정 목록](decisions.md)의 D01~D06 및 D10 중 Kafka/Connect에 필요한 항목을 합의한다.
3. 최신 main에 기반 인프라가 준비되면 Kafka/Connect 실행 기반의 작업 지시서를 작성하고 구현한다.

계획 문서가 완료됐다는 것은 실행 환경이 준비됐다는 뜻이 아니다. 서비스별 실제 연결·복구 검증은 배포 환경의 별도 완료 조건으로 남긴다.
