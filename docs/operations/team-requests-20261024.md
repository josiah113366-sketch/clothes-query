# 팀원에게 보낼 연결 요청 초안

2026-10-24 기준. 전달용 초안만 작성했으며 메시지는 보내지 않았다. 업무 계산·판정 규칙·모델 품질 결정은 각 담당자가 맡고, 인프라에서는 확정된 이미지·경로·계정·자원·배포 연결과 실행 상태를 확인한다.

## 공통 진행 상황

인프라는 현재 API medium 1대와 공용 large 1대로 정리했고 정상 동작 중입니다. 판정 DAG는 실행 중이며 #95의 컬럼 5개와 뷰 4개도 반영했습니다. 지연 수집기는 v2를 보고 있습니다. Spark 전용 풀은 작업할 때 노드가 생기고, 작업이 없으면 내려가는 상태입니다. 아래 항목을 받으면 연결과 실제 실행 확인을 이어가겠습니다.

## Gold B 상시 적재 담당자

Gold B 뷰와 지연 수집기 연결은 끝났습니다. 다만 상시 Spark 적재는 아직 배포 전이라 payment_events/topic_messages/malformed_events에 실제 적재 결과가 없습니다. 배포할 이미지와 실행 설정을 부탁드립니다.

- 최종 ECR 이미지 주소와 digest, 실행 명령·환경변수
- checkpoint S3 prefix와 읽고 쓸 경로
- Driver/Executor 수와 CPU·메모리 요청/상한, 최종 ServiceAccount 이름
- 기존 Spark 4.2.0/Python 3.10.12 이미지 사용 가능 여부. 별도 이미지가 필요하면 그 이미지의 버전
- ECR 저장소나 push 권한이 더 필요하면 저장소 용도와 push할 IAM ARN

받은 자원량으로 Silver·Gold A 배치와 동시에 돌릴 수 있는지 먼저 확인하겠습니다. 상시 Spark는 노드도 계속 유지할 수 있어서, 한 대에 무조건 함께 띄우지는 않겠습니다. 계산·형식 검사 결과와 checkpoint 재시작 기대값은 담당자 확인을 부탁드립니다.

## 판정·조사 담당자

최신 #95 반영 뒤에도 판정 예약 실행은 성공했습니다. 조사도 실제 이미지·ServiceAccount로 모듈 로딩과 Athena 읽기, find_pending까지 확인했고 현재 대기 사건은 0건입니다. Bedrock JP Haiku 실제 호출은 앞서 성공했습니다.

조사→모델→리포트 저장을 함께 확인할 사건과 기대 결과를 부탁드립니다. 사용할 사건 범위/시간, 어떤 리포트와 실행 기록이 남으면 성공인지 알려주시면 됩니다. 제가 임의 사건을 만들거나 조사 DAG를 계속 켜두지는 않았습니다. 원인 분석의 품질·규칙 변경은 담당자 검증 범위로 두고, 실행·권한·저장 연결을 확인하겠습니다.

v2 Sink 정지 사건을 시험하려면 입력이 실제로 발생하는 시간과 정지/복원 구간도 함께 잡아 주세요. 수집기 대상은 bronze-s3-sink-v2/connect-bronze-s3-sink-v2입니다. 정지와 동시에 R3가 뜨는지는 지연 기준·유입·5분 판정 주기에 따라 달라서 기대 시점을 함께 확인하면 좋겠습니다.

## 재처리·대시보드 담당자

대시보드의 실제 Athena 조회와 Airflow 인증은 확인했습니다. 다만 지금 확인한 gold_b_reprocess/silver_gold_a_reprocess는 아직 Airflow에 등록되지 않았습니다. 최종 이름이 다를 수도 있어 실제 사용할 계약을 부탁드립니다.

- 최종 재처리 DAG ID와 배포할 코드/PR
- 승인 화면에서 넘길 요청 JSON 예시(비밀값·업무 원문 제외)
- 완료 이벤트의 source/step·처리 범위와 이를 쓰는 태스크·ServiceAccount

기존 연결은 dashboard/approval-dashboard, 내부 API는 http://airflow-api-server.airflow.svc.cluster.local:8080 입니다. Secret dashboard/airflow-api-client는 username/password 키를 환경변수 AIRFLOW_API_USER/PASSWORD로 참조합니다. 값은 메시지나 Git에 보내지 않습니다. 이 계약을 받으면 승인→DAG 호출→완료 기록→재판정 연결을 대조하겠습니다. 승인자의 실제 계정과 승인 동작은 화면 담당자가 준비해 주세요.

## Silver·Gold A / R6 담당자

첫 Spark 실행의 종료 코드와 Silver·Gold A 결과 PASS, 완료 후 노드 자동 종료까지 확인했습니다. 다만 coverage_status는 UNVERIFIED여서 입력 범위·참조 자료·금액/건수 등 업무 기대값은 담당자 확인이 필요합니다.

조회 연결을 마무리하려면 표 이름·컬럼 타입·Parquet 위치·파티션, 완료 실행을 공개하는 방식, completed_at과 R6가 읽을 완료 목록 계약을 부탁드립니다. current.json만 바꾸면 Athena 조회가 바뀐다고 간주하지 않고, 여러 실행 결과가 합쳐 읽히지 않는지 확인하겠습니다. 업무 스키마나 공개 규칙을 제가 임의로 정하지는 않겠습니다.

## 후기 점수화 / SageMaker 담당자

현재 선택한 릴리스의 manifest·가중치 목록/크기·실행 코드와 Silver 읽기 권한은 확인했습니다. 다만 silver/reviews/에는 아직 입력 파일이 없습니다. 최신 실패 Job은 입력 URI에 버킷 이름이 두 번 들어가고 허용한 Silver 경로 밖이라 다운로드 단계에서 실패했습니다.

실제로 사용할 Silver 후기 파일의 객체 키·파일 형식·기대 건수와 선택할 릴리스를 부탁드립니다. --input-key에는 버킷명이나 전체 s3:// 주소를 제외한 객체 키만 넣으면 됩니다. 현재 실행 코드가 읽는 JSONL/CSV와 Silver 결과 파일 형식이 맞는지도 확인 부탁드립니다. 제가 후기 변환이나 모델 패키지를 임의로 바꾸지는 않았습니다. 입력을 받으면 요청 dry-run과 권한부터 대조하고, 합의한 범위로 실제 Job을 확인하겠습니다.

## 전달 뒤 진행 순서

정보가 오는 항목부터 입력·권한·자원을 먼저 대조하고, 첫 실행은 범위와 기대 결과를 맞춰 확인한다. 상시 Spark·GPU Job·Sink 정지·실제 승인/재처리는 서로 다른 비용/데이터 영향을 가지므로 준비 완료만으로 자동 실행하지 않는다. Git 공유·리뷰와 실제 배포·업무 검증 결과는 따로 기록한다.
