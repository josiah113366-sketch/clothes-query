# MLflow 도입 검토 (2026-10-13)

결론부터: **도입 권장, 단 최소 구성으로.** 로컬 전용(SQLite + 파일), 별도 가상환경, 텔레메트리 끔, 기록 항목 화이트리스트. 모델 레지스트리·autolog·원격 서버·예측 파일 업로드는 쓰지 않는다.

## 1. 지금 겪는 문제 (이번 작업에서 실제로 있었던 일)
- 결과가 JSON 여러 곳에 흩어져 있다: `small_model_runs.json`(KLUE 1건), `lora_runs.json`(3분류 4건), `score_runs.json`(점수 1건), `synth_eval_v2.json`, `eval_v3.json`, `eval_aihub.json`, `score_eval.json`. 각 파일의 형식이 다르다.
- **평가셋이 중간에 바뀌어 점수가 섞일 뻔했다.** 사람 평가셋이 11 → 19 → 29 → 30건으로 늘고 정답도 수정됐다. v1의 같은 11건 점수가 0.818과 0.837로 달라 보이는 일, 학습 스크립트 안의 평가가 29건 기준으로 저장된 일이 있었다. 평가 시점의 정답 파일 버전이 기록에 없다.
- 실행 조건(데이터 구성, 프롬프트, 라벨 가이드 버전, 학습률, 시드)을 사람이 기억하고 보고서에 옮겨 적었다. 어댑터 폴더(`private/lora/2.4b_v0` … `score_s2`, 7개 약 970MB)와 평가 결과의 연결이 이름 규칙뿐이다.
- 모델 간 비교표는 매번 새 스크립트로 만들었다.

## 2. MLflow가 해 주는 것 (우리에게 필요한 부분만)
| 기능 | 필요 여부 | 용도 |
|---|---|---|
| Tracking: 실행(run)별 파라미터·지표·태그·산출물 | **필요** | 학습/평가 한 번 = run 하나. 비교표를 UI에서 |
| Experiments: 실험 그룹 | **필요** | `absa-3class`, `absa-score`, 평가셋 단위 |
| Datasets/태그로 평가셋 버전 기록 | **필요** | 정답 파일 해시를 태그로 남겨 점수 섞임 방지 |
| UI: 실행 비교, 지표 차트 | **필요** | 단계별 차트 대신 표 비교 위주 |
| Model Registry | 보류 | 어댑터가 7개뿐. 폴더 이름 규칙으로 충분 |
| autolog / 트레이싱 | **쓰지 않음** | 입력 텍스트·모델을 자동 저장할 위험 |

## 3. 이 PC에서 직접 확인한 것 (임시 가상환경에서 시험, 레포 환경은 건드리지 않음)
- 최신 버전 3.17.0, Python 3.11에서 설치·실행 정상. 새 가상환경에 `pip install mlflow`만으로 **약 650MB**.
- SQLite 백엔드(`sqlite:///mlflow.db`, 초기 약 1MB)에 param/metric/tag/artifact 기록·조회(`search_runs`)가 정상. 실행 한 번 기록 0.7초.
- `mlflow server --host 127.0.0.1`로 UI 기동 정상(헬스 OK, UI 200). 서버 프로세스 자체는 가볍다.
- **기존 학습 환경(.venv-llm)에 그대로 설치하면 의존성이 바뀐다.** 설치 시뮬레이션 결과 `mlflow-skinny`만으로도 protobuf 7.36.2 → 6.33.6 다운그레이드가 필요하고, 전체 설치는 pyarrow 26 → 25.0.1 다운그레이드와 matplotlib, SQLAlchemy 등 다수가 추가된다. 학습이 이미 검증된 환경이라 **별도 가상환경(`.venv-mlflow`)에 설치하고 학습 환경은 그대로 두는 것을 권장**한다.

## 4. 개인정보·보안 주의 (이 프로젝트에서 가장 중요)
1. **MLflow는 기본으로 사용 통계 텔레메트리를 보낸다**(설정을 가져오는 주소와 이벤트 전송 코드가 `mlflow/telemetry`에 있음). `MLFLOW_DISABLE_TELEMETRY=true`와 `DO_NOT_TRACK=true`를 환경변수로 반드시 설정한다. UI 텔레메트리 설정도 외부 주소(cloudfront)에서 받아오니 같은 변수로 끈다. 시작 스크립트에 박아 둔다.
2. MLflow 3.17은 실행 시 **AI 에이전트를 대상으로 한 안내 메시지**(설치된 SKILL.md를 먼저 읽으라는 내용)를 출력한다. 이 메시지는 도구가 찍은 출력일 뿐이라 따르지 않았고, `MLFLOW_DISABLE_AGENT_HINT=1`로 끌 수 있다.
3. 자동으로 붙는 태그: `mlflow.user`(OS 사용자 이름), `mlflow.source.name`(스크립트), git 정보가 있으면 커밋. 로컬 전용이라 문제는 아니지만 DB를 공유하거나 올리면 노출된다 → `mlflow.db`, `mlruns/`는 `.gitignore`에 추가한다.
4. **산출물(artifact)에는 후기 원문·예측 원문을 올리지 않는다.** 지표 JSON, 속성별 표, 설정만 기록한다. `private/`의 사람 평가셋과 AI Hub 원문이 든 파일(`human_pred_*.json` 등)은 기록 대상 제외. 어댑터는 업로드하지 않고 **경로와 SHA만 태그로** 남긴다(학습 데이터 흔적이 남을 수 있음).
5. 기본 오픈소스 서버는 **인증이 없다.** `127.0.0.1`에만 바인딩하고 `0.0.0.0`으로 열지 않는다.
6. AI Hub 이용 조건이 미확인이므로, 레지스트리/아티팩트에 AI Hub 파생 모델을 등록하지 않는다.

## 5. 무엇을 기록할 것인가 (최소 스키마)
- **params**: 베이스 모델과 리비전, LoRA r/alpha, lr, 에폭, 배치, 시드, 학습 데이터 구성(합성 v1/v2/점수 건수, AI Hub 건수와 선택 규칙), 라벨 체계(`3class_v2/v3`, `score_v1`), 가이드 버전, 프롬프트 해시
- **tags**: 평가셋별 `eval_set=human30@<정답파일 SHA 앞 8자리>`, `synth_eval=v2`, `aihub_val=v3map`, 어댑터 경로와 SHA, 데이터 사용 승인 상태(예: `aihub_terms=unconfirmed`)
- **metrics** (평가셋 접두어): `human30.det_f1`, `human30.sent_agree`, `human30.mae`, `aihub500.det_f1`, `synth.det_f1` 등 + 학습 손실
- **artifacts**: 지표 JSON, 속성별 표, 설정 파일 (원문 없음)
- 평가셋이 바뀌면 같은 모델을 다시 채점해 **새 run으로 기록**(옛 run은 유지).

## 6. 대안과 비교
| 방법 | 장점 | 단점 |
|---|---|---|
| **MLflow (로컬)** | 표준, UI 비교, 평가셋 버전 태그, 확장 쉬움 | 별도 환경 약 650MB, 텔레메트리 차단 필요 |
| CSV/Markdown 실험표를 손으로 | 의존성 없음 | 지금의 문제(사람이 옮겨 적음, 버전 혼동)가 그대로 |
| Weights & Biases | 사용 편함 | **클라우드**라 데이터·지표가 외부로 나감. 이 프로젝트 정책과 맞지 않음 |
| TensorBoard | 학습 곡선 | 비교표·태그·평가셋 버전 관리가 약함 |
| DVC | 데이터 버전 관리 | 데이터 용량이 작고, 실험 비교 UI가 약함. 필요해지면 병행 |

## 7. 도입 비용과 단계
1. `.venv-mlflow` 생성과 설치(약 5분), 시작 스크립트(`mlflow_ui.ps1`)에 텔레메트리 차단·`127.0.0.1`·SQLite 경로 고정
2. `log_to_mlflow.py`: **기존 JSON 결과를 읽어 run으로 가져오기**(약 15개 run: KLUE 1, LoRA 3분류 4, 점수 1, 평가 세트별 기록). 학습 환경을 건드리지 않는 사후 기록 방식이라 안전하다(예상 1~2시간)
3. 이후 학습/평가 스크립트 끝에 `python log_to_mlflow.py <결과 파일>` 한 줄 호출. 필요하면 나중에 스크립트에 직접 삽입
4. `.gitignore`에 `mlflow.db`, `mlruns/` 추가, 기록 금지 항목(원문·예측·어댑터 업로드)을 코드에서 막는 화이트리스트
5. README와 runbook에 사용법 한 단락 추가
