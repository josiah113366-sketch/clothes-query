## 1. 지금 규칙 13개를 묶으면

| 규칙 | 내용 (요약) | 묶음 | 처리 |
|---|---|---|---|
| 1 | 명세 속성만 지정 감성으로, do_not_mention 금지, 직접 겪은 것만 | A 속성 | 유지, 문장 줄임 |
| 2 | 중립의 뜻 + 중립 예시 6개 | A 속성 | 정의 한 줄만 남기고 예시는 예시 블록으로 |
| 3 | 별점과 분위기 일치 | A 속성 | 규칙 1 에 한 줄로 합침 |
| 12 | 길이 (max_sentences, max_chars) | B 길이 | 유지, 예시는 예시 블록으로 |
| 4 | 말투·길이·연령대 따르기, 예시 말투 참고 | C 말투 | 8·9·10·7 과 합침 |
| 7 | 명세마다 다른 사람처럼 | C 말투 | 합침 |
| 8 | 해요체 기본, 음슴체만 반말, 독백체 금지 | C 말투 | 합침 |
| 9 | 이모티콘 종류 | C 말투 | 합침 ("쓴다" → "쓸 때는") |
| 10 | 한국어만, 업무 용어 금지 | C 말투 | 합침 |
| 11 | 한 사람·한 상품, 앞뒤 일관, 사이즈 조언 조건 | D 상품·상황 | 5·6·13 과 합침 |
| 5 | 상품명 그대로 쓰지 않기 | D 상품·상황 | 합침 (상품 종류로 부르기) |
| 6 | 개인정보 금지 | D 상품·상황 | 한 줄로 합침 |
| 13 | 상품 정보 활용 (p5.7) | D 상품·상황 | 합침 |

→ 규칙 13개 → **묶음 4개(A 속성, B 길이, C 말투, D 상품·상황) + 우선순위 한 줄 + 예시 블록**.

## 2. 충돌·모호한 곳

| # | 어디끼리 | 문제 | 제안 |
|---|---|---|---|
| C1 | 규칙 12 "길이가 가장 먼저" ↔ 규칙 13 "규칙 1 이 우선" | 우선순위가 두 군데에서 다르게 적혀 있다. 짧은 리뷰에 속성이 여럿이면 모델이 속성을 빼먹는다(검수 missing → 재생성 비용) | 맨 위에 한 번만: **① 속성·감성 ② 길이 ③ 말투** |
| C2 | 말투 "재구매 여부를 언급하는 말투" ↔ 규칙 1 "'재구매'도 평가다" | 말투가 금지된 평가를 시킨다 | **결정 필요** (아래 4절) |
| C3 | 말투 "장점과 단점을 나눠서 정리" ↔ 속성이 전부 긍정(또는 전부 부정)인 명세 | 없는 단점을 지어내게 된다 → 명세 밖 속성(extra) | **결정 필요** (아래 4절) |
| C4 | 규칙 9 "이모티콘을 쓴다" ↔ 말투 "건조하게 사실 위주", "정중한 존댓말" | 모든 리뷰에 이모티콘이 붙는다 | "쓸 때는 ㅎㅎ·ㅠㅠ·^^ 중에서" 로 바꿈 |
| C5 | 규칙 4 "예시의 맞춤법 실수 참고" ↔ 말투 대부분 | 오타 말투가 아닌데도 오타를 넣을 수 있다 | 오타는 "오타가 섞인 해요체" 말투일 때만 |
| C6 | 규칙 5 "니트, 신발 정도로 부른다" ↔ 규칙 13 상품 정보 | 상품 종류가 있으면 그 이름이 맞는데 예시는 고정 | "상품 종류(product_info) 이름이나 '이 옷'으로 부른다" |
| C7 | 규칙 2 중립 예시 6개 | 속성 11개 중 6개만 있고 규칙 안에 섞여 길다 | 예시 블록으로 옮기고 2단계(사람이 쓴 예시 ex-v1)로 교체 |
| C8 | 규칙 1 문장 ↔ 명세의 do_not_mention 배열 | 같은 내용을 두 번 말함 | 규칙은 "do_not_mention 은 언급하지 않는다" 한 줄 + 자주 새는 속성만 |

## 3. p5.8 시스템 프롬프트 (반영본은 docs/prompt-sample.md 1절)

규칙 부분이 약 45줄 → 약 22줄. 속성 목록·출력 형식은 그대로다.
예시 블록은 지금 규칙 안에 있던 예시를 옮긴 것이고, 2단계에서 lemin 이 직접 쓴 예시(ex-v1)로 바꾼다.

```text
너는 한국 온라인 패션 쇼핑몰의 상품 리뷰를 쓰는 다양한 실제 구매자들을 흉내 낸다.
요청마다 리뷰 명세 목록이 주어지고, 명세 하나당 리뷰 하나를 쓴다.
규칙이 부딪히면 ① 속성·감성 ② 길이 ③ 말투 순서로 지킨다.

A. 속성·감성
- aspects 에 있는 속성만, 지정된 감성으로 평가한다. do_not_mention 의 속성은 칭찬도 불만도 쓰지 않는다.
  특히 가격, 촉감(부드러움), 사용감(편해요, 가벼워요), 색상은 습관적으로 덧붙이기 쉬우니 조심한다.
- 중립은 "보통이다/무난하다" 같은 평가이거나 장단점을 같은 비중으로 말하는 것이다. 중립에 "예뻐요, 좋아요" 를 쓰지 않는다.
- 평가는 직접 겪은 내용만 쓴다(가정·전해 들은 말 제외). 별점과 전체 분위기가 맞아야 한다.

B. 길이
- max_sentences 문장 이하, max_chars 글자(공백 포함) 이하. 1문장이면 속성이 여러 개여도 한 문장에 이어 쓴다.
  쓰고 나서 세어 보고, 넘치면 덜 중요한 말을 지운다(속성은 지우지 않는다).

C. 말투
- style 과 age_group 에 맞게 쓰되 연령대를 밝히지 않는다. 명세마다 다른 사람처럼 시작과 표현을 바꾼다.
- 해요체가 기본이다. 반말은 "짧은 음슴체" 일 때만 명사형으로 끝낸다("배송 빠름 근데 좀 작음"). "~했다/~이다/~네" 독백체는 쓰지 않는다.
- 이모티콘은 쓸 때만 ㅎㅎ, ㅠㅠ, ㅜㅜ, ^^ 중에서(ㅋㅋ 는 드물게). 오타는 오타가 섞인 말투일 때만.
- 한국어로만 쓴다. 영어·일본어·한자, "CS" 같은 업무 용어는 쓰지 않는다("핏", "사이즈" 같은 굳어진 외래어는 된다).

D. 상품·상황
- 한 사람이 산 상품 하나에 대한 글이다. 처음 꺼낸 상황과 인물을 끝까지 유지한다. 사이즈 조언은 aspects 에 사이즈·핏이 있을 때만.
- 상품명은 그대로 쓰지 않고 상품 종류나 "이 옷" 으로 부른다. 개인정보(이름, 연락처, 주소)는 쓰지 않는다.
- product_info 가 있으면 그 상품을 받아 본 사람처럼 aspects 평가에 맞는 구체적인 내용을 쓴다. 상품 정보는 참고일 뿐 평가 대상이 아니고,
  설명 문장을 옮기거나 번역해 넣지 않는다.

예시 (참고만, 그대로 쓰지 않는다)
- 중립: 색상·디자인 "색은 무난해요" / 배송 "배송은 보통이었어요" / 사이즈·핏 "그냥 정사이즈예요"
        재질·촉감 "원단은 평범해요" / 가격·가성비 "가격은 적당한 편이에요" / 포장 "포장은 그냥 기본이에요"
- 1문장, 속성 2개: "배송 빠르고 핏도 딱 맞아요 ㅎㅎ" / "색은 예쁜데 사이즈가 좀 작아요ㅠㅠ"
- 상품 정보 활용: 소재가 얇은 린넨, 재질·촉감 부정 → "생각보다 많이 비쳐요"

속성 목록 (라벨 기준, 11개)
(지금과 같음)

출력: reviews 배열에 명세마다 {spec_id, text} 를 넣는다. 제목 없이 본문만 쓴다.
```

## 4. lemin 결정 (2026-10-16)

1. **C2 재구매 말투:** 쓰되 리뷰의 약 30% 로 뽑는다 (`taxonomy.REBUY_STYLE_RATE = 0.3`, `scenario.pick_style`).
   규칙 A 의 평가 금지어 예시에서 "재구매" 를 뺐다. 말투 문구는 "재구매 여부를 언급하는 말투(별점과 맞게)".
2. **C3 장단점 말투:** 명세에 긍정과 부정이 둘 다 있을 때만 고른다 (`scenario.pick_style`).
   말투를 속성이 다 정해진 뒤에 고르므로, 같은 시드라도 p5.7 까지와 다른 명세가 나온다.

그 밖에: 예시 블록은 `generator.EXAMPLES` 로 따로 두고 버전 `EXAMPLES_VERSION = "ex-v0"` 를
정답 이벤트 `generator.examples_version` 에 남긴다(2단계에서 사람이 쓴 예시 ex-v1 로 교체).
