# 예시 세트 점검표 (ex-vN)

> 브랜치 `sim/review-product-import` · 지시서 2단계 "예시 구성 별 버전관리 및 성능 점검표" · 2026-10-16 시작

생성 프롬프트의 예시 칸(`data/examples/ex-vN.md`)을 바꿀 때마다 같은 조건으로 bench 를 돌려 한 줄씩 적는다.
모델 google.gemma-3-12b-it (도쿄), 검수 모델 = 생성 모델, 재생성 1회.

## 비교 방법

```powershell
rsim bench --yes --n 100 --examples ex-v0     # 기준
rsim bench --yes --n 100 --examples ex-v1     # 같은 --seed(기본 42) → 같은 명세 100건
rsim scorecard                                # 지금까지 실행을 표로 다시 출력
```

- 같은 `--seed` 면 명세(속성·감성·말투·길이)가 같다. 예시 세트의 `seed_sources` 는 명세를 다 만든 뒤 말투 예시를 뽑을 때만 쓴다.
- 100건 = 1차 생성 20회 + 검수 20회 + 재생성분. 한 번에 약 $0.03 (p5.4 기준 1,000건당 $0.26).
- 결과 폴더(`.local/bench/<시각>/`)에는 생성 리뷰 원문이 있어서 커밋하지 않는다. 이 표만 커밋한다.

## 칸 설명 (비율은 명세 수 n 기준)

| 칸 | 뜻 |
|---|---|
| 1차 통과 | 검수 1차에서 속성 누락·감성 차이가 없던 비율 |
| 버림 | 재생성 후에도 실패해서 버린 비율 (시뮬레이터라면 레이크에 안 쓰는 리뷰) |
| 감성/중립 | 1차 감성 차이 건수 / 그중 중립이 낀 건수 (중립→긍정 등) |
| 명세 밖 | 1차에서 명세에 없는 속성을 덧붙인 건수 (버리지 않고 정답 라벨에 추가) |
| 문장·글자 | 최종 리뷰 중 문장 수 초과 / 글자 수 범위 밖 건수 |
| 토큰/건 | 생성 + 검수 호출 합계 ÷ n |

  p5.8 20건 실행은 말투 선택 방식이 바뀌어(scenario.pick_style) p5.4 와 명세가 다르다. 20건이라 비교용으로는 약하다.

- 2026-10-16 이후 실행은 중립 비율을 약 13% → 5% 로 줄인 명세다(scenario.SENTIMENT_BY_RATING). 같은 시드라도 그 전 실행과 명세가 달라서,
  예시 버전 비교는 중립 비율을 바꾼 뒤의 실행끼리 한다(ex-v0 도 다시 돌린다).

## 결과 메모

### ex-v0 vs ex-v1 (2026-10-16, 시드 42, 같은 명세 100건)

- ex-v1 이 나아지지 않았다. 1차 통과 69% → 62%(속성 누락 20 → 29건), 버림 16 → 15건, 중립 오류 12 → 11건으로 비슷하고,
  예시가 길어져 입력 토큰 +16%, 1,000건당 비용 $0.253 → $0.278.
- 1회 실행 100건이라 흔들림이 크다. 1차 실패 명세 중 24건은 두 버전 모두 실패, ex-v0 만 실패 7건, ex-v1 만 실패 14건.
- ex-v1 은 예시 칸과 말투 예시 출처(Gemini 합성 제외)를 함께 바꿔서 어느 쪽 효과인지 나눌 수 없다.
- 예시 내용에서 보이는 원인 (검수 기준 v2: 중립 = "보통/무난/그저 그렇다" 또는 장단점 같은 비중)
  - 중립 예시 상당수가 "문제 없음"이라 검수 기준으로는 긍정이다: "까끌함도 없어요", "몸에 잘 맞아요",
    "촌스럽지 않아요", "마감이 덜 된 부분도 없네요", "교환 응대도 늦지 않게 해주셨습니다".
  - "재질도", "배송도" 처럼 "~도" 로 시작하는 예시가 많아 다른 속성을 덧붙이는 흐름을 보여 준다.
  - 중립 한 칸이 2문장인 곳이 있고 전체가 길어 매 호출 토큰이 는다.

### 중립 5% 명세로 다시 (2026-10-16, 시드 42, 같은 명세 100건)

- 이번에는 ex-v1 이 앞섰다. 1차 통과 75% → 81%, 버림 11 → 7건, 감성 오류 11 → 6건(중립 10 → 5건), 문장 수 초과 37 → 30건.
  입력 토큰은 +5% 지만 재생성이 줄어 1,000건당 비용은 $0.224 → $0.215.
- 중립 비율을 줄인 효과는 두 버전 모두 컸다. ex-v0 기준 1차 통과 69% → 75%, 버림 16 → 11건.
- 그래도 결론은 이르다. 앞선 실행(중립 13%)에서는 ex-v1 이 뒤졌고, 이번 1차 실패 명세는 두 버전 모두 실패 13건,
  ex-v0 만 실패 12건, ex-v1 만 실패 6건이다(엇갈린 18건 중 12 대 6, 우연으로도 나올 수 있는 차이).
- ex-v1.md 는 첫 실행 뒤 한 곳이 바뀌었다("까끌함도 없어요" → "까끌함이 없어요"). 결과에 줄 영향은 작다.

### 시드 7 로 한 쌍 더 (2026-10-16, 중립 5%) 와 두 시드 합계

- 시드 7 에서는 ex-v0 이 앞섰다. 1차 통과 86% vs 81%, 속성 누락 7 vs 11건, 1,000건당 $0.195 vs $0.209.
  버림(7 vs 6건)·중립 오류(6 vs 7건)는 비슷하고, 문장 수 초과는 ex-v1 이 적다(49 vs 43건).
- 두 시드 합계 (명세 200건)

  | | ex-v0 | ex-v1 |
  |---|---|---|
  | 1차 통과 | 161/200 (80.5%) | 162/200 (81%) |
  | 버림 | 18건 | 13건 |
  | 속성 누락 (1차) | 22건 | 25건 |
  | 감성 오류 / 중립 (1차) | 18 / 16건 | 14 / 12건 |
  | 문장 수 초과 / 글자 수 벗어남 | 86 / 24건 | 73 / 30건 |
  | 1,000건당 비용 | 약 $0.210 | 약 $0.212 |

- 결론: 두 버전의 성능 차이는 실행마다 흔들리는 폭 안이다(시드 42 에서는 ex-v1, 시드 7 에서는 ex-v0 이 앞섬).
  ex-v1 은 버림·중립 오류가 조금 적고, ex-v0 은 입력 토큰이 약 8% 적다(건당 972 vs 1,062).

## 차후 개선 (2026-10-18 lemin: 다음 단계로 넘어가고 나중에 한다)

- ex-v2 중립 예시 다듬기: "문제 없음" 문장(검수 기준으로는 긍정) 대신 "보통이에요, 무난해요, 그저 그래요" 나
  장단점을 같은 무게로 쓴 짧은 문장(15자 안쪽)으로 바꾸고, "~도" 로 시작하는 예시를 뺀다. 말투 예시 출처는 ex-v1 과 같게 둔다.
- 비교할 때는 두 시드(42, 7) x 100건씩 돌려 합계로 본다. 한 번 100건은 실행마다 1차 통과가 5~7%p 흔들렸다.
