# agent/prototype

탐지 규칙(R1~R4)을 **가짜 데이터**로 시험하는 프로토타입이다. 실제 Athena나 Kafka에 연결하지 않는다.

## 실행

```
cd agent/prototype
python3 evaluate_v3.py      # 규칙 설정별 탐지율·오탐·걸린 시간 표 (표준 라이브러리만 사용)
```

## 파일

| 파일 | 역할 |
|---|---|
| `sample_data.py` | 사건 3개(PG 장애, 소비 지연, 스키마 오염)와 주문·메시지 생성 |
| `ledger_v3.py` | 1분 단위 원장 모양의 가짜 데이터 생성 |
| `detect_v3.py` | 규칙 R1(PG 원인 실패), R3(소비 지연), R4(깨진 메시지) 판정 |
| `evaluate_v3.py` | 30회 반복 시험과 결과 표 |
| `modes.py` | 시연 모드(일상·중간 3배·폭주 10배)별 탐지 시간 시험 |
| `REPORT.md` | v3 시험 보고서 |

## 모드별 결과 (`python3 modes.py`, 판정 5분마다, 가짜 데이터 30회)

시뮬레이터 확률표(2026-10-16)의 분당 주문 수를 하루로 환산해 넣었다. 걸린 시간은 장애 시작부터 규칙이 이상으로 판정할 때까지의 분(평균 / 최대)이다. 규칙은 R1(최근 15분 PG 원인 실패 3건 이상)이다.

**평소 PG 원인 실패가 없다고 가정했을 때** (옛 가정)

| 모드 (분당 주문 → 하루 환산) | 사건 1 PG 장애 | 사건 2 소비 지연 | 사건 3 스키마 오염 | 오탐(하루) |
|---|---|---|---|---|
| 일상 새벽 (0.7 → 1,008) | 11 / 20 | 5 / 5 | 5 / 5 | 0.03 |
| 일상 하루평균 (5,000/일) | 5 / 5 | 5 / 5 | 5 / 5 | 0.03 |
| 일상 저녁 피크 (6.3 → 9,072) | 5 / 5 | 5 / 5 | 5 / 5 | 0.03 |
| 중간 (19 → 27,360) | 5 / 5 | 5 / 5 | 5 / 5 | 0.07 |
| 폭주 (63 → 90,720) | 5 / 5 | 5 / 5 | 5 / 5 | 0.03 |

**평소 PG 원인 실패가 시도당 1.15%(확률표 값)일 때** — 같은 규칙(3건 이상)으로는 **오탐이 크게 늘어난다.**

| 모드 | 오탐(하루) | 비고 |
|---|---|---|
| 일상 새벽 | 0.77 | |
| 일상 하루평균 | 4.00 | |
| 일상 저녁 피크 | 10.17 | |
| 중간 | 56.43 | 장애 전에 이미 울려서 "걸린 시간"이 음수가 되어 의미 없음 |
| 폭주 | 18.97 | 위와 같음 |

- 주문이 많을수록 평소 PG 원인 실패도 15분에 3건을 쉽게 넘는다. **고정 건수 기준은 주문량에 따라 달라져야 한다.** 건수 기준 k를 바꿔 보면(코드는 `evaluate_v3.score`의 `r1_k`) 어느 모드에서도 잘 맞는 k 하나는 없었다. 규칙 R1을 "PG 원인 실패율이 평소보다 많이 높다" 같은 주문량에 맞춰 바뀌는 기준으로 바꾸는 것이 다음 일이다(**미정**).
- 이 프로토타입은 하루 내내 같은 주문 속도라고 가정한다. 실제 일상 모드는 시간대 곡선을 따른다(새벽 분당 0.7 ~ 저녁 6.3).
- 사건 2·3이 5분으로 나오는 것은 판정이 5분마다 돌아 결과가 5분 단위로 나오기 때문이다. 사건 2는 평소의 20배 유입 급증이라 시뮬레이터의 폭주 모드와 정의가 다르다.

## 읽을 때 주의

- `python3 evaluate_v3.py`가 기본으로 보여 주는 표는 **판정을 1분마다 돌린 경우**(`step=1`)다. 팀이 제안한 판정 주기는 5분이라서, 5분 주기 결과는 `kw=dict(step=5)`로 따로 재야 한다. 같은 규칙(R1 최근 15분 3건 이상)으로 쟀을 때 PG 장애 탐지는 5분마다 판정하면 하루 900건 평균 13분(최대 30분), 하루 3,600건 평균 5분(최대 10분)이다.
- 위 모드별 결과는 시뮬레이터 확률표의 **제안값**(하루 주문 약 5,000건, 확정 필요)을 기준으로 한다. 하루 900건을 가정했던 옛 시험은 `evaluate_v3.py`의 기본 표에 남아 있다.
- `evaluate_v3.py`의 허용 지연 값(20/7/7분)은 옛 기준이라 확정값이 아니다. 허용 지연은 팀에서 정한다.
